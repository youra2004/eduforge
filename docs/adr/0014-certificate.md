# ADR-0014: Certificate signing and verification

- Signing (F10-R2, D-26): Ed25519 over the canonical payload (JSON, keys sorted at every level, no whitespace; `canonicalize` in `certificate/canonical.ts`, repeated on its own in `scripts/verify-certificate.mjs`). The private key is `CERT_SIGNING_KEY` (PKCS#8 DER, base64; `pnpm generate-signing-key` prints one and saves nothing); the DB holds public keys only (`signing_keys`). The `kid` is the first 16 characters of the base64url SHA-256 of the raw public key, so a key and its id cannot drift. The active key is registered in `signing_keys` on first use and the others are marked retired; retired keys stay in `/.well-known/jwks.json` (a JWK set) because they still verify what they signed. Rotation = put a new key in env. Percentages in the payload are rounded to one decimal so the stored JSON is stable.
- Issuance: only for the caller's own `passed` exam attempt, one per attempt (unique `assessment_id`; asking again returns the same one). The exam issues it as it ends (best effort); the result page offers "get certificate" when that did not happen (no key, a hold). It is refused while the attempt has a `pending_review` strike (ADR-0013) and with no key configured. The LLM description (`certificate_summary`, logged in `llm_runs`) sees the course title and skill levels only, never the holder; a failed call means no certificate yet, not one without a text. A confirmed strike annuls the pass and revokes its certificate in the same transaction (`annulAttempt`).
- Verification and revocation (F10-R3, F10-R4): `/verify/<id>` and `GET /api/certificates/<id>` are public and re-check the signature on every read against the key stored for `kid`; the stored SHA-256 and the `certificate_id` / `kid` inside the payload must also match. `status` is `valid` or `revoked` (the signature of a revoked certificate stays good). The revocation reason is visible to admins only; the public side shows the date. The QR code is made on the server from the request host. Print/PDF (F10-R5) is the page's print stylesheet.
- The holder name is part of the signed payload, so an issued certificate does not change when an account is edited. What happens to it when an account is deleted is not decided: there is no account deletion yet (SPEC OQ-12).
