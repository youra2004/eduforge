# ADR-0015: Recommendations job and demo mode

- Job (F7, D-16): `runRecommendations` is plain code in `packages/core`; the worker schedules it (06:00, `recommendations.daily`) and the admin's "run now" button calls the same function inside the web app, because the page needs the result at once. For each student with an active course or a test in 30 days: SQL metrics (7/30-day mastery trend, weak skills, courses with no finished test in 7 days, nodes failed and not passed since), then one `recommendation` LLM call through `LLMClient` (logged in `llm_runs`, Mock responder, metrics only: no name, email or answers) for 1–3 tips. One failing user is `failed` and stores nothing; the next run tries again.
- "Nothing changed" (F7-R2): the row keeps `metrics_hash` (SHA-256 of the rounded metrics, a column added to the DATA_MODEL table); the same hash as the newest row, or no signal at all, means no call. At most one row per user and day (unique key, `CHECK` of 1–3 items), so one call per day.
- Demo mode (D-32, NFR-6): a "day" is 24 h / `TIME_SCALE`: `day` stores `1970-01-01 + floor(epoch / scaled day)` days, so at `TIME_SCALE=1440` it is a date in the far future but the one-run-per-day limit and the schedule (`*/1 * * * *`) shrink with it. Pauses were already scaled in M05/M07/M09; `/admin/demo` shows them. Seed data is marked: `users.is_demo`, "(демо)" in names, "[ДЕМО]" in the course title, a banner on the student page; `pnpm seed-demo` refuses to run twice (`DEMO_SUFFIX` is for tests and e2e).
