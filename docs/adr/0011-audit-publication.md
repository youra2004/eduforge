# ADR-0011: Audit, publication and expert review

- The audit is a worker job (`audit.run`) over core's `runAudit`. Submitting is one guarded `UPDATE` (editable status, `audit_attempts < AUDIT_MAX_ATTEMPTS`) that also sets `auditing`, so a double click or a sixth run cannot pass; a deterministic precheck (stage 0) reports graph, content (every node has an item), transcript and pool problems before that and costs no run. Stage 0 runs again in the job. The volume cap uses the node count only (`AUDIT_VOLUME_CAPS`, default `6:3,12:6,20:9`): question volume is already gated by the pool minimums (F3-R6), and the SPEC gives no question-based step (OQ-5). Any failed stage (structure, conformity gate, uncovered skill) ends the attempt in `changes_requested` with the list; scoring is not paid for. If the provider keeps failing, the run is given back (`audit_attempts - 1`) and the version returns to `changes_requested`; unfinished audits are re-queued when the worker starts.
- Scoring takes `AUDIT_SCORING_RUNS` (5) independent calls with `cache: false`, all in `llm_runs` (subject = the version); the level median is by order (lower on a tie), the hardness median by value. `rating` stays null while a version waits for an expert. The author's view is an allow-list: rating, level, hardness, feedback per category, skill verdicts, and only a boolean "size limited the score" (no cap, no bands). Course text is data for the auditor, and a 10 can never be published without an expert, so prompt injection in a course cannot buy the top rating. The audit Mock reads the prompts back and judges by word overlap and text volume.
- Publication is the author's click (`ready_to_publish → published`, also after an approved 10); an author can reopen a ready version to improve the score (D-09). An expert rejection leaves the version in `expert_review` and the author chooses `improve` (→ `changes_requested`) or `publish_9`; a review belongs to the current attempt (created after that attempt's scoring row), so an old rejection never blocks the next audit. Only the assigned expert decides, an expert cannot review their own course, approval needs every checklist item ticked and a rejection needs a comment. An editable version whose audit runs are used up can be copied into a new version (otherwise it would be a dead end); every other non-published status is frozen as before (ADR-0005). Deleting a node in the editor removes its content and questions with it; deleting a skill that still has questions is refused.
