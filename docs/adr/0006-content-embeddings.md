# ADR-0006: Content storage, embeddings and retrieval

- The vector size is fixed in the migration (`vector(1024)`, OQ-2); `EMBEDDING_DIM` must match it or the app refuses to start. A different size means a new migration and a full re-embed. Default model: `text-embedding-3-large` with `dimensions=1024` (handles Ukrainian). Embedding and Whisper calls go through `EmbeddingClient`/`TranscriptionClient`, are logged to `llm_runs` with hashes and sizes only (no chunk text, no vectors) and have Mocks; the OpenAI-compatible adapters are tested against a stubbed `fetch` only.
- `retrieve` filters with `node_id IN (...)` in SQL and orders by `distance + 0`, so Postgres scans the (small) allowed set exactly instead of walking the approximate HNSW index and filtering afterwards, which can return too few or the wrong rows. The HNSW index stays for unfiltered use.
- Indexing is by content hash (`content_items.indexed_hash`): a node is re-embedded only if its text changed. Web saves queue a job; a worker sweep every minute re-queues anything missed. Uploaded mp4s live in `STORAGE_DIR` on local disk (200 MB limit, served with Range support to users who can see a version using them); Whisper only runs for uploaded files, so a video by link needs an author transcript.
