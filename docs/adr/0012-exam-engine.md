# ADR-0012: Exam engine

- Everything runs on server time (P1). Each call into an exam first applies the clock (`examClock`): a question ends at `shown + limit` (90 s `mcq`/`short`, 5 min `open`) or at the exam deadline, whichever is first; an answer at the exact deadline counts, a later one gets `exam_time_expired`. Questions that ran out while nobody looked are closed lazily, each at its own deadline, with `{timedOut: true}` and no points; an abandoned exam is graded the next time it is read (no job), and the tutor ignores a running exam past its deadline. Autosave stores the typed answer as a draft only to restore it after a reload; a draft left at the deadline is not scored.
- Set assembly: the questions are spread evenly over the skills round by round (shares differ by one), a short skill gives what it has and the others fill up, and the order is random; the seed is stored. A pool smaller than the rating's count gives a shorter exam instead of blocking a course that passed publication (F3-R6 needs only 3 per skill); a skill with no exam question blocks it. An unrated version uses the lowest profile. Profiles, limits, pass mark and level mark are config (`EXAM_PROFILES`, `EXAM_*`, P2). Only the current question leaves the server, with no verdicts (D-18b, F3-R2).
- Rounds are derived from the attempts (`examRounds`), not stored: passed, failed and annulled attempts are used; two used in a round start the pause of `EXAM_COOLDOWN_SECONDS / TIME_SCALE` from the last one; then round + 1. One attempt = one row, or a chain of rows for interruptions: an interruption closes the row as `interrupted`, keeps the time left, and the resumption inserts a new row with the same attempt number, the carried count and a freshly drawn set (old rows stay for research). The third interruption (limit 2) ends the attempt as `failed` with `meta.reason = interruptions_exceeded`, whatever the points. No strike or ban is ever written here; strikes and the camera are M10. While the clock is stopped by an interruption the student can use the tutor, an accepted gap (time cannot keep running for a network fault).
- `assessments.per_skill` holds `{skillId, name, pct, level}` for an exam (levels at 90 % / 70 %, inclusive) next to the node tests' `pKnown`; the exam never touches BKT. Starting is serialised per student and course with an advisory lock, so two clicks give one exam. The pre-check screen lists camera, fullscreen, lighting and consent as placeholders; desktop-only is a notice there, not a server rule.
- An answer is reserved under the lock before it is graded (the LLM call for `short`/`open` runs outside the transaction), so a reload past the deadline while grading cannot close it as missed; the next question's time starts at that moment, not after grading. Interrupting resets the answered part: the new set replaces it and only the time left carries over, so the two allowed interruptions are the student's to use. A browser connection drop under 10 s is not reported as an interruption; a tab closed mid-exam keeps the tutor closed until the exam deadline. The exam ends only when every question has points; a reserved answer still unscored after 120 s (a request that died) counts as no points, and an interruption while the last answer is being graded is ignored (earlier ones are not).
