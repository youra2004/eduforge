# ADR-0013: Proctoring and strikes

- The browser only reports; the server decides (P1, F9-R8). Browser events are a closed list (`BROWSER_EVENTS`): an unknown type is refused, a server-only type (`face_mismatch`, `phone`…) cannot be claimed, and the severity is never read from the request. Hard: leaving fullscreen, focus lost past `PROCTOR_FOCUS_GRACE_SECONDS` (the browser reports `awayMs`, the server re-checks it), copy/paste/cut, devtools (F12/Ctrl+Shift+I/J/C and a docked-window heuristic). A hard event annuls the attempt (`annulled`, counted as used) and writes a confirmed strike in the same transaction; events after the attempt ended are dropped. Soft: faces (MediaPipe, 3 looks in a row), frame checks, typing, a second reference photo (a reload mid-exam). Their weights (`rules.ts`) add up to `risk_score` (stored on the attempt); at `PROCTOR_RISK_THRESHOLD` (60) one `pending_review` strike opens for the admin queue, with no ban and no stop. One strike per attempt (unique): a hard event after a soft flag confirms that same strike. Confirming a soft strike also annuls its attempt, even a finished pass.
- Ladder: the n-th standing strike (confirmed or under appeal) gives 7 d, 30 d, then permanent (`users.exam_ban_until` / `exam_banned_forever` are derived from the strikes, longest wins, and scaled by `TIME_SCALE`). The ban is read only by `startExam`, so learning is untouched. An appeal (one, only while `confirmed` and unresolved) keeps the ban until an admin overturns it (ban recomputed from what stands) or rejects it (closed). An overturned strike leaves the attempt `annulled`; it is not restored. The appeal text and the admin's decision go to the attempt's append-only `proctor_events` log, so `DATA_MODEL.md` §10 needed no new columns. A pending soft strike is invisible to the student; M11 must not issue a certificate while the attempt has a strike in `pending_review`.
- Privacy (NFR-2, D-27): no biometrics at rest. The reference photo lives only in the page's memory and travels with each frame; after a reload the gate asks for it again and the server notes `reference_retaken` as a soft signal. A frame is checked in memory and kept only when it triggered an event: AES-256-GCM into `STORAGE_DIR/evidence/<uuid>.enc` (key `EVIDENCE_KEY`, env only; no key → no evidence is written and the request fails loudly), `expires_at` = `EVIDENCE_RETENTION_DAYS` (30), row in `proctor_evidence`. The worker deletes expired rows and files daily at 03:00 and once at start; closing a case (dismissed, overturned, appeal rejected) deletes its frames at once. The Vision check is logged in `llm_runs` (`vision_check`) by the frame's SHA-256 and size, never the image. Frames come at the server's pace (at least half of `SNAPSHOT_INTERVAL_SECONDS` apart); the browser picks a random moment inside each window.
- `ProctorProvider`: `MockProctorProvider` plays scenarios (`normal`, `other_face`, `second_person`, `phone`, `gaze_away`) that the browser names with `?proctor=` in demo mode only (`PROCTOR_PROVIDER=mock`); the real one ignores the hint. `HttpProctorProvider` talks to a face-comparison + Vision service at `PROCTOR_SERVICE_URL` (`POST /compare`, `POST /vision`, base64 JSON); no such service exists in this repo and the adapter has not been run against one. A failing checker is a technical fault (`snapshot_failed`, info), never a strike. MediaPipe (`@mediapipe/tasks-vision`) loads its wasm from jsDelivr and the face-detector model from Google storage, so the exam needs those hosts; self-hosting them is a deploy choice.
- The server hides the question until the camera gate was reported (`camera_ready`) and refuses answers before it (`camera_required`); consent is checked when the exam starts (`consent_required`). The camera and the fullscreen need the student's click, so the gate sits on the exam page and the exam clock already runs while it is passed. A native `confirm()` leaves fullscreen, so "technical problem" asks inline. A camera that stops is an interruption (F8-R6), not a violation. "Desktop only" is checked in the browser (width and pointer), not on the server.
